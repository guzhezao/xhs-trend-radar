# XHS Trend Radar

用 **MiniMax Code 内置浏览器**抓小红书高赞笔记，逐条打开验证后产出一份
**可视化 HTML 报告**：带赞藏评图表、发布新鲜度散点、驱动力分布，
每条笔记都有能点开的真实链接和「先做哪个」的判断。

不导 cookie，不配 headless，不装 Playwright。

```
你：帮我出一份小红书上"AI 做自媒体"的高赞热点报告，10 条
Mavis：（右侧浏览器自己动起来）
      → 关键词扩展 → 搜索 → 按点赞重排
      → 逐条打开验证 → 选题分层 → 生成 HTML 报告（图表 + 可点击链接）
```

**范围：只做小红书、只抓热点笔记内容。** 找达人/找博主/选号、抖音等其他平台都不覆盖。

## 为什么只能在 MiniMax Code 里跑

不是许可证限制，是技术上跑不通。而且**跑不通的方式很阴**。

### 未登录不会失败，会静默给你空结果

实测（2026-07-29，`web_fetch` 请求搜索页）：

| 观察项 | 实际返回 |
|---|---|
| HTTP 状态 | **200** |
| HTML | 完整页面，导航栏和频道 tab 都在 |
| `__INITIAL_STATE__.search.feeds` | **`[]`** |
| `global.hasWebSession` | `false` |
| 搜索框 placeholder | 「登录探索更多内容」 |

它不封你、不给验证码、不返回错误码。页面骨架全都在，笔记数组是空的。

一个只判断 HTTP 状态码的脚本会认为自己成功了，然后交付一份
"这个关键词最近没什么热点"的空报告。**用户拿到的不是错误，是错误的结论。**

这是这个 skill 拒绝提供降级方案的核心原因。

### 四件必须的依赖

| 依赖 | 说明 |
|---|---|
| **已登录的浏览器会话** | 直接用右侧面板里你自己的登录态，不需要导 cookie |
| **opaque ref 快照** | `inspect` 返回不透明元素句柄，绕开 Vue scoped + 构建 hash 类名 |
| **快照带可见文本** | 靠标题文本在快照里比对定位，应对瀑布流位置错乱 |
| **`snapshotId` 分页续读** | 应对虚拟列表滚动后的元素卸载 |

所以 `SKILL.md` 第 0 节有前置检查——环境不满足直接退出，不会给你一份假结果。

## 安装

macOS / Linux：

```bash
git clone https://github.com/cool111111/xhs-trend-radar.git \
  ~/.minimax/skills/xhs-trend-radar
```

Windows PowerShell：

```powershell
git clone https://github.com/cool111111/xhs-trend-radar.git `
  "$HOME\.minimax\skills\xhs-trend-radar"
```

抓取依赖 MiniMax Code 的内置已登录浏览器；报告生成器使用 Python 3 标准库，
可在 Windows、macOS 和 Linux 上运行，不需要安装第三方 Python 包。

然后在 MiniMax Code 里直接说"帮我出一份小红书 XX 的高赞热点报告"。

### 为什么不用 MCP / Playwright

同类方案通常要下平台专用二进制或装 200MB chromium，再跑独立登录工具扫码存
`cookies.json`，起常驻服务，配 `stealth.min.js` 反检测——它们的前四步都在搭环境。
本 skill 第一步就是业务，因为登录态问题在 MiniMax Code 里不存在：
右侧浏览器就是真浏览器，本来就带着你的登录态。

## 三块核心设计

### 一、不给假结果

抓到 ≠ 抓对。所以：

- 每条走「点击 → 独立 URL → 标题作者比对」，比对不上就丢弃
- 三级标注：`✓已验证` / `搜索兜底` / `定位失败`，混合交付时必须并存可区分
- 统计口径写"目标 10 / 已验证 7 / 兜底 3"，不写"全部拿到"
- 排序口径老实写"综合排序前 N 里按点赞重排"，不写"点赞前 N"
- 空结果**先排查登录态**，不直接输出"该词无热点"
- 进度落在磁盘 `data.json`，上下文被压缩也能接着跑，不重头再来

抓取工具普遍只管「能不能抓到」，不管「抓到的对不对」。这套标注就是补这块。

### 二、抓完给判断，不只给排行榜

一个按点赞排的列表用户还是不知道先做哪个。每条追加四项判断：

- **阶段**：窗口开着 / 收窄 / 关了
- **驱动力**：看赞藏评的**结构**而非总量（收藏 > 点赞 → 实用型）
- **门槛**：可直接做 / 需素材 / 需资源
- **相关性**：强相关 / 可延展 / 不相关

最后按可执行性分三组：**现在就做 / 排期做 / 只做参考**。

事实和判断在输出里分块，不让"驱动力：实用"看起来像平台字段。

### 三、产出是填不满就露馅的 HTML 报告

交付物是一份浅色系单文件 HTML 报告：顶部 KPI 事实结论、一段导语、三张图表
（赞藏评对比 / 发布新鲜度散点 / 驱动力分布）、逐条笔记明细、可执行性分组。
**Chart.js 内联进单文件，双击就开、离线可用，点击图表柱子/气泡直接跳对应笔记。**

图表逻辑全部写死在模板里（`assets/report-shell.html`），抓取时只产出一份 `data.json`，
再用跨平台的 `scripts/build-report.py` 拼装——**模型不写 HTML，没有从零手写图表翻车的空间。**

关键在于**这些图表和 KPI 只有拿到真数据才填得出来**：藏赞比要藏的数据、
新鲜度散点要发布时间、驱动力分布缺数据的条目落进灰色扇区。markdown 清单可以
只列标题蒙混，HTML 报告不行——**偷懒会被图表公开展示出来。**

只读公开内容。不绕反爬、不刷量、不做写操作、不采集非公开个人信息。
